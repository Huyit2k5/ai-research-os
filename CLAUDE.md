# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local-only Kaggle account manager for small research teams (shared workspaces): the first module of a planned "AI Research OS". The UI copy, error messages and docs are in Vietnamese. Keep new user-facing strings in Vietnamese.

## Commands

The only supported run setup is Docker Compose from the repo root. The database is a hosted **Supabase** Postgres; there is no local db container. It needs a root `.env` with `CREDENTIAL_ENCRYPTION_KEY` (32 bytes, base64url) and `DATABASE_URL`, which is the Supabase **Session pooler** URL (IPv4, port 5432) ending in `?sslmode=require&uselibpqcompat=true`. On Vercel the same URL must use the **Transaction pooler** (port 6543): the session pooler allows 15 clients and each serverless instance's `pg` Pool holds up to 10, so it fills up and every DB route returns 500. The app sets no session state and uses no named prepared statements, so transaction mode is safe; `migrate-auth.mjs` (advisory lock) needs session mode. The README has a key generator, and `.env.example` shows the URL format.

```powershell
docker compose up --build -d   # build and start web on http://127.0.0.1:3000
docker compose down            # stop
```

Inside `apps/web` (npm, lockfile committed): `npm run dev`, `npm run build`, `npm run start`, `npm run format` / `npm run format:check` (Prettier). Running outside Docker requires `DATABASE_URL` and `CREDENTIAL_ENCRYPTION_KEY` in the environment.

If host port 3000 is taken, set `WEB_PORT` and a matching `BETTER_AUTH_URL` (e.g. `http://localhost:3001`) in `.env`. The API's CSRF check compares `Origin` against `BETTER_AUTH_URL`, so a mismatch makes every write fail with "Nguồn yêu cầu không hợp lệ".

There is no linter or CI. `npm run format:check` and `npm run build` (Next.js type-checks with strict TS) is the main check. `tests/auth-isolation.mjs` is an end-to-end auth/ownership/CSRF script. It needs a disposable database: migrate it, seed one ownerless `compute_accounts` row, then start a server on port 3002 against it. Run `AUTH_TEST_BASE=http://localhost:3002 node tests/auth-isolation.mjs`. `tests/papers-isolation.mjs` (`PAPERS_TEST_BASE=http://localhost:<port>`) checks paper/note/token/tag/bulk/export ownership, MCP auth and rate limiting. `tests/runs-isolation.mjs` (`RUNS_TEST_BASE=http://localhost:<port>`) checks run ownership, compare, validation, CSRF and the MCP run tools (Kaggle capture only up to the ownership check). `tests/docs-isolation.mjs` (`DOCS_TEST_BASE=http://localhost:<port>`, server and test both with MinIO `S3_*` env and the server with `STORAGE_LIMIT_MB=1`; MinIO: `docker run -d -p 127.0.0.1:59000:9000 -e MINIO_ROOT_USER=minio -e MINIO_ROOT_PASSWORD=minio-secret-123 quay.io/minio/minio server /data`, create the bucket with `scripts/storage-check.mjs --create-bucket`) checks documents end to end. `tests/doc-categories.mjs` (`DOCCAT_TEST_BASE`, no MinIO) checks categories and result docs, including MCP. `tests/run-requests-isolation.mjs` (`RUNREQ_TEST_BASE`, optional `RUNREQ_TEST_DB` for the expiry/running checks) checks run requests: auth, token-cannot-approve, race, validation, MCP; connections use a dummy Kaggle token, so approve stops at Kaggle by design. `node tests/save-kernel.test.mjs` unit-tests the SaveKernel body builder. `scripts/kaggle-push-check.mjs <account_id>` pushes a tiny private CPU script with a real connection. `tests/password-reset.mjs` (`RESET_TEST_BASE`, `MAILPIT_API`; server with `SMTP_URL=smtp://127.0.0.1:51025` from `docker run -d -p 127.0.0.1:51025:1025 -p 127.0.0.1:58025:8025 axllent/mailpit`) checks the reset flow; Better Auth allows 3 reset requests per minute, so wait a minute between runs. Each of those two creates two `papers-iso-*` / `runs-iso-*` users per run and does not delete them. All three need a disposable database. Never point them at the real Supabase database: they create users, and the auth test claims ownerless connections.

## Architecture

Everything lives in `apps/web`, a Next.js 16 / React 19 app. There is no Python backend and no separate API service.

There is no linter or CI. `npm run build` (Next.js type-checks with strict TS) is the main check. `tests/auth-isolation.mjs` is an end-to-end auth/ownership/CSRF script. It needs a disposable database: migrate it, seed one ownerless `compute_accounts` row, then start a server on port 3002 against it. Run `AUTH_TEST_BASE=http://localhost:3002 node tests/auth-isolation.mjs`. Never point it at the real Supabase database: it creates users and claims ownerless connections.
- **Server lib: `lib/server.ts`** (`server-only`):
  - A global `pg` Pool.
  - `initialize()` is a legacy fallback that creates a bare `compute_accounts`. Real schema changes go in `scripts/migrate-auth.mjs`, which must stay idempotent. Any new table must be added to its `ENABLE ROW LEVEL SECURITY` list, or Supabase's public Data API can read it.
  - Token encryption is hand-written **Fernet-compatible** AES-128-CBC + HMAC. It must stay compatible with tokens written by the former Python backend.
  - `kaggleCall(token, method, body)` POSTs to `https://api.kaggle.com/v1/kernels.KernelsApiService/<method>` with a Bearer token, mirroring the official Kaggle SDK's wire protocol. There is no Kaggle CLI or SDK dependency.
- **Auth.** Better Auth (email + password) is configured in `lib/auth.ts`, mounted at `app/api/auth/[...all]`, and stores data in the same Postgres. Its secret is derived from `CREDENTIAL_ENCRYPTION_KEY` unless `BETTER_AUTH_SECRET` is set. Workspaces are the Better Auth `organization` plugin (tables `organization`, `member`, `invitation`; the plugin list in `migrate-auth.mjs` must match `lib/auth.ts`). The API resolves the workspace on every request: the session's active one if the user is still a member, else their oldest, else a new "Cá nhân" one. It scopes connections by `workspace_id`. `owner_id` is the connection's creator. Any workspace member may use a connection (verify, sync, logs, stream, run capture; the token is decrypted server-side and never returned), but only the creator or a workspace owner/admin may replace its token or delete it. The first registered user claims connections that have no owner. The container's start command runs `scripts/migrate-auth.mjs` first: it holds an advisory lock while it migrates the Better Auth tables and `compute_accounts`, and enables RLS on all of them.
- **Live logs.** `notebook-logs-stream` proxies Kaggle's `/v1/kernels/logs/stream/...` and re-emits it as SSE (`status` / `log` / `done` / `error` events), with a 30-minute cap and 1 MB buffer limits. `logs-screen.tsx` consumes it.
- **Persistence.** Connections (label, username, encrypted credential, verified flag, creator, workspace) live in `compute_accounts`. Each sync also upserts the latest quota and first 100 notebooks into `account_sync` and appends a `quota_snapshots` row (90-day retention); `GET /api/accounts/:id/sync` returns the stored copy and `page.tsx` loads it on start. Any workspace member can sync and read it; the last sync by anyone wins. Notebook run status (`notebook-status`, polled every 10 s while active) and logs are not stored. Credentials are never returned to the client.
- **Paper library + MCP.** Separate route files, not the catch-all: `app/api/papers/**` (search OpenAlex + arXiv with `page`/`year_from`/`year_to`, `import` by DOI/arXiv id, paged list filtered by `q`/`source`/`status`/`tag`, PATCH incl. `tags`/`read_status`, `tags`, `bulk`, `export` (BibTeX), notes with PATCH), `app/api/tokens` (personal API tokens, only a SHA-256 hash is stored, shown once) and `app/api/mcp` (stateless JSON-RPC MCP server, 33 tools: 15 paper + 8 run + 6 doc + 4 run-request, Bearer-token auth only; `delete_paper`, `merge_papers` and `delete_run` carry `destructiveHint`). Papers also have `refresh` (OpenAlex batch by `openalex:`/`doi:` filters, exact-title fallback, fills only empty fields), `duplicates` and `merge` (one transaction; also re-points `experiment_runs.paper_id` when that table exists, because it is `ON DELETE SET NULL`). All shared logic and lazy table creation live in `lib/papers.ts`: tables `papers` (incl. `venue`, `venue_type`, `read_status`, `tags TEXT[]`, `cited_by_count`, `work_type`, `metadata_refreshed_at`; `read_status` is legacy), `paper_reads` (per-member read status, no row = `to_read`; `withReads()` replaces `read_status` with the caller's own and adds `read_count`/`member_count`/`readers`; list filters `status` and `readers=none|others` are about the caller; merge keeps each member's most advanced status), `paper_notes`, `api_tokens`, `api_usage`, all RLS-enabled; new columns are added with `ADD COLUMN IF NOT EXISTS`. Limits there: `MAX_PAPERS` 2000, `MAX_NOTES_PER_PAPER` 200, 20 tags per paper, `rateLimit()` (Postgres-backed; search/import 20/min, MCP 120/min). Duplicates match on DOI/arXiv/OpenAlex id or normalised title + year (`normTitle`). `listWhere()` is the single filter builder shared by list and BibTeX export. `searchLibrary` ranks with weighted tsvector (title A, abstract B). Search results carry `saved_id` via `markSaved()`. `toBibtex()` picks `@inproceedings`/`@article` from `venue_type`, else `@misc`, and keeps particles (“van den Oord”) in the last name. `app/papers-screen.tsx` + `app/papers.css` (scoped `pl-*` classes) are the UI; abstracts are de-LaTeXed for display only. No LLM or API key is used; AI access is MCP-first (Claude calls in).
- **Experiment runs.** `lib/experiments.ts` owns table `experiment_runs` (RLS-enabled, lazy-created; one row per Kaggle notebook version, unique on owner/account/ref/version, or `source='manual'`; `MAX_RUNS` 5000/user, 5000 history points). `captureRun()` reads the version's output via `ListKernelSessionOutput`: `ros_run.json` (≤2 MB, Kaggle/Google hosts only) first, `@@ROS_CONFIG` / `@@ROS_METRIC` log markers as fallback and to merge config; `GetKernel` adds env + code snapshot best-effort. Re-capture never overwrites user-edited name/notes/tags/paper_id and keeps old data when nothing is found. `notebook-status` auto-captures on a terminal status (skipped if captured <2 min ago); there is no background scheduler. REST under `app/api/runs/**` (list, manual run, get/PATCH/DELETE, `capture`, `compare`); MCP adds `list_compute_accounts`, `list_runs`, `get_run`, `compare_runs`, `capture_run`, `log_run`, `update_run`, `delete_run`. The notebook-side helper is `docs/ros_tracker.py` (stdlib only); the format contract is in `docs/EXPERIMENT_TRACKING.md` and must match the parser.
- **Documents.** `lib/documents.ts` owns `documents`, `document_papers`, `document_runs` (lazy, RLS). Kinds `idea | report | other`; ideas have `status` `new | trying | chosen | dropped` (other kinds reject a status; leaving `idea` clears it). Text docs keep `body` (markdown/html, ≤512 KB) in Postgres. Files go to an S3-protocol store via `lib/storage.ts` (`aws4fetch`; Cloudflare R2 in production, MinIO in tests; env `S3_ENDPOINT`/`S3_REGION`/`S3_BUCKET`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`, a trailing `/<bucket>` on the endpoint is stripped). **File bytes never pass through the app**: `POST /api/docs/uploads` reserves a `pending` row and returns a presigned PUT bound to type+length; the browser PUTs; `POST /api/docs/:id/complete` HEAD-checks size/type, else deletes object and row. `GET /api/docs/:id/file` 302s to a 5-minute presigned GET (`?download=1` forces attachment, `?url=1` returns JSON so `fetch()` avoids a cross-origin redirect that would send `Origin: null`). Inline only for PDF, PNG/JPEG/GIF/WebP and HTML; `text/*` is served with `charset=utf-8`. HTML is only ever rendered in `<iframe sandbox="">` (no scripts). Limits: 25 MB per file, `STORAGE_LIMIT_MB` (default 9000) for the whole project, 5000 docs per workspace, 30 uploads/min. `/api/docs/**` accepts sessions and personal tokens; MCP adds `list_docs`, `get_doc`, `create_doc`, `update_doc`, `delete_doc`. `mergePapers` copies `document_papers` to the kept paper. UI: `docs-screen.tsx` (list, write, upload) and `app/docs/[id]/page.tsx` (viewer; .docx via `mammoth`). The bucket's CORS policy must list every app origin. `scripts/storage-check.mjs` verifies a store.
- **Run requests (push to Kaggle with approval).** `lib/run-requests.ts` owns `run_requests` (lazy, RLS). AI (token/MCP `push_notebook`) only creates `pending` rows; `approve`, `reject` and `run-now` routes are **session only** (`owner(req)` without `allowToken`) so no token can spend GPU. Approve claims the row with one `UPDATE … WHERE status='pending'` (race-safe), then `GetKernel` (inherit settings) → quota check for GPU/TPU → `SaveKernel` (`SaveAndRunAll`) → `running`; any failure returns it to `pending` with `error`. `lib/save-kernel.ts` (pure, no server imports) builds the body: Kaggle **drops attached sources that a new version does not resend**, so unspecified fields always inherit from the current version. `refreshRequest` follows `running` rows (on page/tab view or `get_run_request`; no background job), captures the run and `linkCapturedRun` adds it to the idea's `document_runs`; `notebook-status` also calls `linkCapturedRun`. Approve with `{ save_only: true }` (or a request with `run: false`) sends `kernelExecutionType: "QuickSave"` (new version, no cell runs) and ends in status `saved`; `timeout_minutes` (1–720, none by default) becomes `sessionTimeoutSeconds`. Kaggle names versions `v<N>`: every `versionLabel` sent must be `v${n}`, a bare number is 404 (verified 2026-11-19). Limits: code ≤ 2 MB, 50 pending per workspace, 30 requests/hour and 10 approvals/min per user, pending expires after 7 days. UI: tabs in `runs-screen.tsx` + `run-requests-panel.tsx` (also `RunModal` for Notebooks), review page `app/run-requests/[id]/page.tsx` (code, `diff` against the current Kaggle code, `LiveLog` from `live-log.tsx`, shared with `logs-screen.tsx`).
- **Scope (workspaces).** Connections, papers, notes and experiment runs are shared per workspace (`workspace_id`); `owner_id` records the creator. `lib/workspace.ts` is the single resolver: `sessionWorkspace(req)` (active org if still a member, else oldest, else a new "Cá nhân"; used by the catch-all route and `owner()` in `lib/papers.ts`) and `tokenWorkspace()` (API tokens are personal but bound to the workspace active when created; removed members' tokens get 403). Any member can view, add and edit; deleting/merging needs `canManage()` (creator or owner/admin); a note is edited only by its author; Kaggle connections are usable by every member (the token never leaves the server); only the creator or an owner/admin replaces a token or deletes a connection, and a Kaggle run is unique per (connection, notebook, version) whoever captured it. Rows from before workspaces (`workspace_id` NULL) are adopted into the creator's oldest workspace on their next request (`adoptLegacyRows`). Paper/run tables are still created lazily in `lib/papers.ts` / `lib/experiments.ts` (RLS enabled there), not in `migrate-auth.mjs`. Limits are per workspace (5000 papers, 10000 runs); rate limits stay per user.
- **Frontend.** `app/page.tsx` is a single client component that owns all state (accounts, sync data, modals) and renders the Accounts screen inline. `workspace-screen.tsx` holds the members, invite and workspace switcher screen, plus `AcceptInvite` for `/?invite=<id>` links. `connector-screens.tsx` renders the other screens (overview, quota, notebooks, logs); `papers-screen.tsx` and `runs-screen.tsx` (with `papers.css` / `runs.css`, scoped `pl-*` / `rn-*` classes) are the paper library and experiment screens and exports the shared `Screen` / `Account` / `SyncData` types. Styling is plain CSS (`style.css`, `screens.css`) with `lucide-react` icons; there is no Tailwind or component library.
- **Code style.** Prettier (`apps/web/.prettierrc.json`, print width 120) formats `app`, `lib`, `scripts` and `tests`. Write one statement per line and run `npm run format` before committing; `npm run format:check` must pass.

## Docs vs. reality

- `docs/KAGGLE_CONNECTOR_ROADMAP.md` is the current task checklist for this module.
- `docs/AI_Research_OS_Architecture_Roadmap.md` is the long-term target design: FastAPI, Celery, pgvector, LangGraph, and a `apps/api` + `workers/` layout. **None of that exists yet.** The project deliberately moved to a Next.js-only backend. Do not scaffold Python services or the target layout unless asked.
- The Kaggle username is an unverified label. Sign-up is open, with no email verification. Password reset is Better Auth's `sendResetPassword` over SMTP (`lib/mail.ts`, nodemailer; env `SMTP_URL` + `MAIL_FROM`, off when unset; link lands on `/?reset=1&token=…`, handled in `auth-screen.tsx`; a reset revokes all sessions); `scripts/reset-password.mjs` is the no-SMTP fallback. So the app binds to `127.0.0.1` only and must not be exposed publicly.
